Overview

The code appears in the cell, token by token, in the notebook you already have open. Not in a side panel you copy out of, and not on disk behind a stale tab.

In development. Early, pre-1.0, and still changing between releases. Settings and the bridge API can change — read the changelog before upgrading.

  • InstallationGet it running — about five minutes
  • Your first cellEvery step, start to finish
  • HelpSomething went wrong

What it is good at

  • Writing a cell from a description, using your real column names — because it can see the cells above it and what they printed.
  • Fixing an error without you explaining it. It reads the traceback.
  • Editing the live document, so Ctrl+Z works normally and nothing is overwritten when you save.

What it will not do

  • Edit a notebook that is not open in VS Code. It does not touch files on disk.
  • Run code you did not approve. Writing a cell and running a cell are separate decisions.
  • Work with the Claude CLI on Windows. Use an API key there.

Installation

About five minutes. There is no Marketplace listing yet, so you install a .vsix by hand.

1. Check the prerequisites

NeedWhyCheck
VS Code 1.90+The notebook editing APICode → About
Jupyter extensionOpening and running notebooksSearch ms-toolsai.jupyter
A Python kernelRunning cellsOpen a notebook → Select Kernel
Claude Code, logged inWhere the code comes fromclaude --version

Without the Jupyter extension and a kernel the extension still writes cells — it just cannot run them.

2. Download the .vsix

Take the newest file from the Releases page. It is named ai-notebook-live-<version>.vsix.

Releases marked Pre-release are older versions kept for history. Some have known security bugs and say so at the top. Always take the one marked Latest.

3. Install it

  1. Open the Extensions view (Ctrl+Shift+X)
  2. Click the … menu at its top right
  3. Install from VSIX… and pick the file
  4. Reload the window when prompted

Or from a terminal, in the folder you downloaded it to:

code --install-extension ai-notebook-live-<version>.vsix

On a Mac the code command does not exist until you run Shell Command: Install 'code' command in PATH from the command palette, so the menu route is usually faster.

Verifying what you downloaded (optional)

Each release also carries a SHA256SUMS. The .vsix is a zip and is not byte-reproducible, but the code inside it is:

unzip -p ai-notebook-live-<version>.vsix extension/dist/extension.js | sha256sum

Compare with the extension/dist/extension.js line in SHA256SUMS. If they do not match, do not install it.

4. Choose how it reaches a model

Open the control panel: Ctrl+Shift+P → AI Notebook: Control Panel, or click the ✨ AI item in the status bar. It tells you which provider it found.

RouteHowCost
Claude Code CLI (default)Install Claude Code and log inUses your existing plan
Anthropic APIAI Notebook: Set Anthropic API KeyBilled per token

With provider on auto, an API key wins — including one exported as ANTHROPIC_API_KEY or ANTHROPIC_AUTH_TOKEN in your shell, which is easy to forget you did and is billed per token. Set provider to claude-cli to always use your plan.

The key is stored in VS Code's secret store, never in settings.json.

5. Check it works

Open any .ipynb, click a cell, press Ctrl+Alt+G. If a prompt box appears, you are ready.

Updating and uninstalling

Installs are manual, so nothing will prompt you. Download the newer .vsix, install it the same way (add --force if the CLI complains), and reload. Going back works identically.

To uninstall: Extensions view → gear icon → Uninstall. To remove what it stored, clear the API key first, then delete ~/.ai-notebook-live/ — which holds only the bridge's token file, and only if you used the bridge.

Your first cell

Every step, from an empty notebook to working code.

1. Open a notebook

Open any .ipynb. The extension only activates for notebooks. Look for ✨ AI in the status bar — that is your sign it is awake.

No ✨ AI? If your file opened in a plain text editor, close it and reopen with Open With… → Jupyter Notebook.

2. Pick a kernel

Click Select Kernel at the top right. You can write cells without one, but you cannot run them.

3. Generate a cell

Click the cell you want the new one to appear below, then press Ctrl+Alt+G. Type what you want, in plain words:

load sales.csv and show the first few rows

A new cell appears below your selection and fills in as the model writes.

On models with extended thinking there can be a pause before any text appears. That is normal — it is thinking, not stuck.

4. Decide whether it runs

By default the extension asks before running anything it wrote: Run it, Always run these this session, or cancel. Nothing executes without you clicking.

5. Do not like it? Undo

Ctrl+Z. Everything it does is an ordinary undoable edit. Undo follows the stream, so it steps back through the generation rather than reverting it in one go — hold it down.

6. Revise it

Click the cell, press Ctrl+Alt+R, say what to change:

use a bar chart instead, and sort descending

If the revision fails, your original comes back in a single undo step.

7. Fix an error

Run a cell, watch it fail, then click Fix the Error on the cell toolbar. You do not have to explain what went wrong — the cell and its traceback are both sent.

8. Explain a cell

Explain This Cell adds a markdown explanation above the cell. Useful for notebooks other people will read.

The whole loop
Ctrl+Alt+G   describe a cell   → written below your selection
Ctrl+Alt+R   revise the cell   → rewritten in place
Fix the Error                  → reads the traceback, rewrites the cell
Explain This Cell              → markdown explanation above it
Ctrl+Z       undo anything

Making it write the way you want

systemPromptExtra is appended to every prompt — the single most useful setting here:

"aiNotebookLive.systemPromptExtra":
  "Beginner class: keep code simple, avoid list comprehensions, comment every line."

It can be set per workspace, so a teaching folder or a team repo carries its own house style. It is ignored in a workspace you have not trusted.

Two things worth knowing early

It sees your outputs. By default it sends the preceding cells and what they printed, which is what lets the model use your real column names. It also means dataframe contents go to the model — see Privacy & security.

If you type while it writes, it stops. It keeps your version and leaves the rest alone, and tells you it did.

Why some settings cannot be set per project

Settings that decide execution or open a socket are machine-scoped, so a repository you clone cannot change them: execution, bridge.execution, bridge.autoStart, bridge.port, claudePath, autoRun.

In a workspace you have not trusted, systemPromptExtra and provider are ignored, generated code never runs, the bridge does not start, and the Claude CLI is run outside the folder so that folder's hooks and CLAUDE.md cannot take effect.

Running generated code

Writing a cell and running a cell are separate decisions, and you own the second one.

SettingDefaultApplies to
aiNotebookLive.executionaskCells you asked Claude for
aiNotebookLive.bridge.executionneverCells another program pushed in

Each is never, ask or always.

What ask means

A modal dialog shows the code and waits. For your own generations you get Run it, Always run these this session, or cancel.

On the bridge it works differently, because an HTTP caller cannot be left hanging: the caller is answered immediately with pending, and the dialog appears afterwards. So an agent-pushed cell can run a few seconds after it arrives — or never, if you say no.

There is no always button for agent-pushed code. One click on one agent's harmless-looking cell would otherwise have approved every later push from any local program for the life of the window.

If the dialog had to clip the code to fit, it says so — "Showing the first N of M characters" — and the always button is withheld. You are not asked to approve forever on the strength of a cell you could not finish reading.

An agent can ask, and never override

A bridge caller may request execution with run=1, but a request can only lower this decision, never raise it. If your policy says never, run=1 changes nothing. Nothing executes in a workspace you have not trusted, whatever the settings say.

If you type while it writes

The extension gives way: streaming stops, your version is kept, nothing runs, and you are told. Over the bridge the caller gets a 409 rather than a success it did not earn.

Revoking a session grant

Open the control panel — Approved for this session shows the grant and lets you take it back. Reloading the window also clears it.

The agent bridge

A token-authenticated HTTP endpoint on 127.0.0.1 that lets other tools on your machine read the open notebook and write cells into it.

Off by default. Read Privacy & security before turning it on.

Why it exists

Most tools that edit notebooks write the .ipynb on disk. That does not appear in a tab you already have open, and is overwritten the moment you save. The bridge edits the live document instead.

Turning it on

  1. Open a notebook
  2. AI Notebook: Start Local Agent Bridge
  3. AI Notebook: Copy Agent Bridge Example Command gives you a working command
printf 'print("hello from an agent")' | node <path>/bin/nbpush.js

nbpush ships inside the installed extension.

--replace destroys what was in that cell. Ctrl+Z restores it, but only if you notice. Use --list first.

The HTTP API

GET  /health         state of the target notebook
GET  /cells          the live contents, including unsaved edits
POST /cell           {"code": "..."} in one shot
POST /cell/replace   rewrite one existing cell, by ?index=
POST /cell/stream    raw body, streamed into the cell as it arrives

Authenticate with the x-ai-notebook-token header. The token is in ~/.ai-notebook-live/bridge.json. Query parameters go in the query string only — the body carries content and nothing else.

expect= — the guard worth using

Pass the source you last read, and the replace is refused if the cell has changed since, instead of destroying something you have not seen.

/cells clips a long cell and marks it truncated. Never replace a truncated cell from what you were shown — you do not have its full text, so you cannot form a correct expect.

Status codes

CodeWhen
401No token, or the wrong one
400Body is not a JSON object · produces no content · unrecognised kind · position not a whole number · /cell/replace with no index=
404Unknown path
405Wrong method
409No notebook open · notebook= matches none or more than one · expect= mismatch · you edited the cell while it was being written
413Body over 1 MiB

Two behaviours worth knowing

An ambiguous notebook= is refused. The match is a substring of the whole path, so notebook=/ would match every open notebook. Rather than pick the first, the bridge answers 409 and names the candidates.

Invisible characters are repaired, and reported. A non-breaking space, or a zero-width joiner inside an identifier, would make a cell the kernel cannot run. These are rewritten rather than refused, and the response carries repaired: <n> so a caller is never silently edited.

Connecting Codex

The bridge is also an MCP server, so a tool that speaks it can add cells as a first-class action rather than by running a shell command.

Why this matters for Codex

Codex's extension edits notebooks on disk. A .ipynb written on disk does not appear in a tab you already have open, and is overwritten the moment you save. Going through the bridge edits the live document instead.

Privacy & security

What leaves your machine, and what the bridge can reach.

What is sent to generate a cell

  • the cells before the insertion point (contextCells, 12 by default)
  • their outputs and error tracebacks, if includeOutputs is on — it is by default
  • the notebook's file name only, never its path
  • the kernel language, and your instruction

Cell outputs routinely contain more than people expect: dataframe contents, file paths, API responses, anything you printed. The default is on because it is what makes the tool good — the model reuses your real column names instead of inventing them.

The one exception

Fix the Error always sends the traceback, even with includeOutputs off. Asking to fix an error is asking to send that error. With the setting off it sends the traceback and nothing else — the cell's ordinary printed output stops.

Where it goes

With the API provider, to Anthropic under your API key. Nothing else does.

With the Claude Code CLI provider, through your existing Claude Code session — and more travels than the list above. The CLI is started inside your workspace folder, so it behaves the way Claude Code always does there:

Any CLAUDE.md that applies to the folder is part of the request, and Claude Code may read other files in the folder and send their contents if answering needs it.

If that folder holds anything you would not send to Anthropic, use the API provider for it, or open the notebook somewhere else. In a workspace you have not trusted, the CLI is run outside the folder instead, so neither its CLAUDE.md nor its hooks apply.

Telemetry

This extension collects none of its own. Nothing is sent anywhere except the provider you chose, for a request you triggered — with one thing worth naming: while the bridge is running, any local program holding the token can read the open notebook, including cell outputs.

What the bridge is, and is not

It protects you from:

  • The network. It binds 127.0.0.1 and is never exposed.
  • Web pages. The token goes in a header, which forces browsers to preflight; preflights are refused. Requests carrying an Origin, or a Host that is not loopback, are refused too.
  • A token in your shell history. Copyable commands never contain it, and a token in the query string does not authenticate.

It does not protect you from any program already running as you that can read ~/.ai-notebook-live/. That program can read your notebook, add cells, overwrite existing ones, and — if you have allowed it — run them. That is the point of the feature, and why it is off until you turn it on.

The token file is created 0600 in a 0700 directory, with O_EXCL so it will not follow a symlink. On Windows those modes are not meaningfully enforced.

Reporting a problem

Use GitHub's private vulnerability reporting — the Report a vulnerability button on the repository's Security tab. Please do not open a public issue for a security bug.

Help

Organised by what went wrong, not by which part of the code owns it.

Start here, always: AI Notebook: Show Log. It records what was sent where, and why a cell did or did not run. Most questions below are answered in one line of it. The first line gives the version — quote it in any bug report.

Nothing happens

There is no ✨ AI in the status bar

The extension only activates for Jupyter notebooks. If your .ipynb opened in a plain text editor, reopen it with Open With… → Jupyter Notebook. The item also hides when the active editor is not a notebook.

The shortcut does nothing

Ctrl+Alt+G only binds inside a notebook — click inside a cell first. If another extension claimed the key, check Keyboard Shortcuts and search aiNotebookLive.

Provider problems

"Could not find the claude command"

Either install Claude Code and log in, or set aiNotebookLive.claudePath to the absolute path. The error message itself offers to set it for you. Find it with which claude.

It is billing my API key when I wanted my Claude plan

With provider on auto, an API key wins — including one exported in your shell. Set provider to claude-cli.

"Anthropic rejected the API key"

The stored key is wrong or expired. Replace it, or clear it and fall back to the CLI.

Upgrading from v0.6.1 or earlier? Those versions showed "Anthropic is not defined" for every API error, including a bad key. Fixed in v0.6.2 — if you see that string, upgrade.

The Claude CLI does not work on Windows

It is not supported there. The CLI is installed as a .cmd, which this extension neither finds nor launches correctly, and the obvious workaround would turn a launch problem into a shell-injection surface. Use an API key on Windows — everything else, including the bridge and MCP server, works normally.

Generation problems

It hangs with no output

Extended thinking often pauses before any text appears. timeoutSeconds (default 300) gives up, but that clock is measured from the last token, so a long think is never interrupted — only true silence is.

It wrote into the wrong place

Cells are inserted below your selection. To replace instead, use Revise This Cell.

It stopped halfway and kept my text

You typed into the cell while it was writing. The extension gives way on purpose — your version is kept and nothing runs. Just ask again.

Execution problems

It is not running anything

execution defaults to ask. The dialog is modal and may be behind another window. If you pressed Esc earlier, that is recorded as a deny for the session — reload the window, or reset it in the control panel.

Nothing runs no matter what I set

You are in an untrusted workspace. Generated code never executes there and the bridge does not start. Use Manage Workspace Trust if you mean to.

Bridge problems

Everything returns 401

The token changes every time the bridge restarts. Re-read ~/.ai-notebook-live/bridge.json, or re-copy the example command, and restart any agent that cached it.

A push returned 409

Message mentionsMeaning
no notebook openOpen one
matches more than oneYour notebook= fragment is ambiguous — the message names the candidates. Use a longer one
matches noneThe fragment matches nothing open
expect=The cell changed since you read it. Re-read and retry
you edited the cellYou typed into it mid-write; your version was kept

A replace returned 400

Most often no index=. As of v0.6.2 the bridge refuses to pick a cell for you — earlier versions treated a missing index as cell 0 and overwrote it.

nbpush --replace hit the wrong notebook

Upgrade. Before v0.6.2, --replace and --list silently ignored --notebook and used whichever notebook was focused.
